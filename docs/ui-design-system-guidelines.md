# UI 设计系统准则

本准则适用于 Yumerin 的 Android 界面和共享 Compose Multiplatform 界面。它定义组件选择、材质、布局与复用规则；具体页面的交互要求仍由对应页面文档和用户明确指定的设计决定。

## 组件选择：Miuix 优先

- 需要使用按钮、输入框、卡片、偏好行、导航、弹层等界面组件时，先检查项目当前版本的 Miuix 是否提供语义和交互都匹配的组件；有合适组件就优先用 Miuix。
- 只有在 Miuix 没有所需组件，或该组件无法满足明确的平台行为与功能要求时，才使用 Jetpack Compose 原生组件或平台组件。不要仅因原生组件更熟悉，就绕过已有的 Miuix 对应组件。
- 原生回退组件也必须接入 Yumerin 的共享主题、材质和布局规范。必要时用项目级封装统一外观与交互，不在页面里复制一套私有样式。
- `Row`、`Column`、`Box`、`Modifier`、布局、绘制和语义等 Compose 基础能力继续作为组装组件的工具；组件库优先规则约束的是面向用户的控件和容器。

## 材质与外观：集中、统一、可切换

- 这里的“材质”指组件的视觉表现，例如实色、半透明、模糊、阴影、边缘高光和描边；它与 Jetpack Compose Material 3 的库名称不是一回事。
- 组件材质由统一的全局外观状态和 design-system tokens 控制，并提供全局切换能力。一个外观选项应一致地作用于同类卡片、按钮、输入框、导航和弹层；不能让每个页面各自硬编码一套材质。
- Miuix 组件与原生回退组件应读取同一套主题语义、颜色和材质 tokens，使同一屏幕里的控件保持协调。新增控件必须能响应全局材质切换。
- 页面不得随意写死颜色、透明度、模糊、圆角、阴影和描边值。确需局部差异时，将差异做成可复用的 token 或组件变体，并说明适用范围。
- 主题强调色与材质模式是不同的外观维度；当前强调色选择不能代替全局材质切换。材质选项的名称和数量由后续产品设计决定，本准则不预设具体选项。

## 布局与排版

- 页面使用一致的 Scaffold、系统栏和安全区处理；标题区、正文区、分组、卡片、表单、列表和底部操作遵循同一套页面结构与对齐规则。
- 页面边距、区块间距、行高、控件尺寸、圆角和触控区域使用共享的语义化尺寸规范。新增尺寸先查找并复用现有 design-system tokens；确需新增时集中定义，不在多个页面分别复制数值。
- 标题、正文、辅助说明、标签和按钮文字使用主题中的对应文字层级；避免在页面内任意指定字体大小、字重和颜色。
- 同类组件保持一致的信息层级、对齐、状态反馈和间距。窄屏、长文本、键盘弹出和滚动内容也沿用同一布局规则，不依赖单一设备尺寸。

## 共享组件与例外

- 同一组件或同一交互/视觉模式在两个及以上位置重复出现时，应先评估并优先抽取到共享 design-system 或项目级组件，减少重复代码并集中维护。
- 抽取后的组件用参数表达真实的主题差异；不要为了消除少量重复，把不同语义和行为强行合并成难以理解的通用组件。
- 用户明确指定某个页面或控件必须采用特定设计时，该要求优先于通用准则。例外只作用于指定范围；不得以统一规范为由改掉用户要求保留的设计。若后续维护者可能误改，应把例外记录在对应页面说明或验收条件中。

## UI 验收

- UI 和外观改动要检查实际渲染的 Android 界面；涉及材质切换时，要确认切换后各类组件同步变化。编译成功本身不能证明布局和材质一致。
